Contrato REST

La UI cambia,
el contrato no

Todas las pantallas hablan con api.js. En modo local resuelve contra el store; en remoto hace HTTP contra este contrato. Cambiar de uno a otro no requiere tocar una línea de interfaz. 

# Local (por defecto): sin servidor, persistencia en el navegador
http://127.0.0.1:8787/app/#/home

# Remoto: API mock o backend real
http://127.0.0.1:8787/app/?api=remote&base=http://127.0.0.1:8788/api#/home
Un solo adaptador. createApi(store) expone products, createOrder, updateProduct, adminStats… Cada método decide local o HTTP. Las pantallas no saben en qué modo están (salvo Perfil, que lo muestra).

node api/mock/server.mjs
# MEGA API mock · http://127.0.0.1:8788/api

Sin dependencias. Datos en memoria: al reiniciar se restauran los seeds. CORS abierto solo para desarrollo.

  "customer": {

    { "productId": "p1", "colorId": "lime", "qty": 2 }
  ],
  "payment": "card",
  "delivery": "express"

El servidor recalcula precio, envío y total. Si el stock no alcanza:

Modo remoto en la app

El parámetro base permite apuntar a cualquier backend. La app usa ?api=remote&base=… y recuerda el modo en localStorage["mega.api"]. Para volver a local, ?api=local.

El mock no persiste. Cada reinicio vuelve a los seeds, y las órdenes creadas se pierden. Para pruebas de persistencia usá el modo local (localStorage).

Checklist para producción

  1. Autenticación y roles. Proteger todo /admin/* y filtrar órdenes por usuario.
  2. Transacciones. Crear orden + descontar stock en una sola transacción con bloqueo.
  3. Idempotencia. Idempotency-Key en POST /orders y eventos de pago.
  4. Pagos. Webhook firmado; nunca marcar pagado desde el cliente.
  5. Validación. Esquema (Zod/Ajv) en cada entrada; límites de tamaño.
  6. Observabilidad. Request ID, logs estructurados, métricas de latencia y errores.
  7. Seguridad. Rate limiting, CORS restringido, headers, secretos fuera del repo.
  8. Backups. Base de datos con restauración probada, no solo configurada.
